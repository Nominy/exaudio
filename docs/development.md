# Developing Exaudio

For application usage, see [Get started / Начать работу](getting-started.md). For the component contract, see the [Rust extension SDK](../sdk/rust/README.md). Architecture and release procedures live in [architecture.md](architecture.md) and [releasing.md](releasing.md).

## Windows prerequisites

- Git.
- [Rustup](https://rustup.rs/), using the toolchain declared in the repository's `rust-toolchain.toml`. Do not replace the pinned version to work around a compiler error without checking the dependency requirements.
- Visual Studio Build Tools with **Desktop development with C++**, the MSVC x64 toolchain and Windows SDK.
- CMake on `PATH` for native audio dependencies, including libopus.
- WebView2 Runtime and a WebGPU-capable GPU/driver only when exercising Windows local inference. The inference runtime and models install separately from application compilation.
- `cargo-nextest` for the workspace test command. The .NET 8 SDK and `dotnet tool restore` are packaging prerequisites, not requirements for end users.

Use the repository root as the working directory. A full first build takes a while; later builds are incremental.

## Select the build you need

```powershell
# The editor: Local mode, subtitle formats, basic checks, command palette; no Babel, no AI
cargo editor

# The same plus the Gold AI tools, without Babel
cargo run -p exaudio-app --no-default-features --features palette,local,formats,basic-checks,gold --locked

# Core shell only: deliberately no bundled modes, formats, checks or AI
cargo run -p exaudio-app --no-default-features --locked

# All batteries, including Babel
cargo run -p exaudio-app --locked
```

`cargo editor` is an alias in `.cargo/config.toml` for `cargo run -p exaudio-app --no-default-features --features palette,local,formats,basic-checks`. `exaudio-app` is the Cargo package and binary name used during development. Packaged releases use the Exaudio name. The default `batteries-included` feature selects `palette`, `local`, `formats`, `basic-checks`, `gold` and `babel`; changing the build feature set is different from enabling/disabling an installed extension. Bundled native extensions live under `extensions/`: `palette` (command palette, `Ctrl+Shift+P`), `local`, `formats`, `lint-basic`, `gold`/`gold-ui` and the `babel-*` family.

**First-party code and build inputs:** Helper, reviewer/drafting and Babel integration extensions are the Exaudio author's own developments, not proprietary third-party extensions. Every build above, including the default all-batteries one, builds from a fresh checkout: the Babel linter's rule data (`babel-lint-data.json`, `error-category-names.json`) is tracked in `extensions/babel-lint/assets`. Only the parity fixtures described below are private. Keep credentials and private task content out of source and public fixtures.

Building the app does not install AI model weights. Source builds are not Velopack installs and do not perform packaged-app update checks. Do not expect `cargo run` to follow the stable or alpha feeds.

### Babel data bundle (parity tooling only)

The private Babel data bundle holds the fixtures the repository cannot carry: `lint-parity.json`, the transcript corpus with the issues Babel's linter and the Helper custom linter report (generated by `tools/lint-parity/generate.mjs`), and optionally `waveform-parity/display-signal.js` and `waveform-parity/wavesurfer.js`, copied Babel web code that `tools/waveform-parity/run.ps1` drives. No crate reads it at build time; `cargo build` and `cargo nextest run --workspace` pass without it.

`tools/babel-data.json` pins the bundle by SHA-256. `tools/update-babel-data.ps1 -Fetch` copies `babel-data-<sha256>.tar` from the author's SSH store (`-Remote`, `-RemoteRoot`) into the per-user cache (`%LOCALAPPDATA%\Exaudio\build-cache` on Windows, else `$XDG_CACHE_HOME/exaudio/build-cache` or `~/.cache/exaudio/build-cache`), verifies it and unpacks it into `target/babel-data`; a matching cached archive avoids the network. Without `-Fetch` the script publishes the stage and updates the pin, so do not omit it for ordinary setup.

The three parity tests in `exaudio-babel-lint` (`matches_babel_on_every_parity_case`, `matches_helper_custom_linter_on_parity_corpus`, `project_lint_matches_gold_and_helper_on_the_parity_corpus`) read `lint-parity.json` from `$EXAUDIO_PARITY_DATA`, else from `target/babel-data`. When the file is absent they print a note on stderr and pass without checking anything, so a run that must cover them needs the fetched bundle (or `EXAUDIO_PARITY_DATA` pointing at an unpacked copy). `tools/waveform-parity/run.ps1` takes the downsampler from the same stage unless `-BabelDisplaySignal` names another copy.

## Synthetic development material

For an account-free, synthetic demo, set these variables in a PowerShell terminal before launching the editor:

```powershell
$env:EXAUDIO_OPEN_DEMO_ON_START = '1'   # open the two-speaker demo instead of Start
$env:EXAUDIO_AUDIO_SILENT = '1'         # keep the playback path, emit silence
cargo editor
```

Unset them afterward with `Remove-Item Env:EXAUDIO_OPEN_DEMO_ON_START, Env:EXAUDIO_AUDIO_SILENT` when returning to normal use. `EXAUDIO_LOG_AUDIO_PLAYBACK=1` logs one line per transport start. The demo is an original Russian dialogue synthesized with Piper voices; [the generator](../tools/demo-audio/generate.py) records the source voices and dataset provenance. Do not regenerate it just to run the app, and do not substitute private platform tasks in public screenshots or test fixtures.

## Working on the editor

Editor work happens in `crates/`. `extensions/` is optional (Babel, AI, formats, checks, modes) and the editor builds and runs without it; `crates/exaudio-app/tests/crate_boundaries.rs` fails if a crate under `crates/` starts depending on an extension.

| Where | What |
|---|---|
| `crates/exaudio-core` | `Project`, `Segment`, `EditorCommand`, `CommandHistory` (undo/redo). |
| `crates/exaudio-editor` | The editor without UI. `edit::EditorDoc` is the facade: every user operation is a method that returns an `Outcome` (status line + `Effect`s for the view to perform) or an `EditError`. `edit/doc/*` holds those methods by concern, `edit/*.rs` the pure rules they call. `editor_model::EditorSession` is the view state (selection, playhead, viewport, zoom, loop, track filter); `timeline_model` and `transcript_model` build what the views draw (`TimelineLaneView`, `TranscriptRowView`); `edit/keymap.rs` declares every action and its default keys. |
| `crates/exaudio-shell/src/editor` | The GPUI views. `model.rs` (`EditorModel`: owns the `EditorDoc` and the audio engine, emits `EditorEvent`), `mod.rs` (`EditorScreen`: layout, key routing, extension panels), `toolbar.rs`, `status_bar.rs`, `timeline/` (`mod.rs` view and pointer handling, `paint.rs`, `geometry.rs` hit-testing, `overview.rs`, `rail.rs`), `transcript/` (`mod.rs` list, `row.rs`, `fast_row.rs`, `row_style.rs`, `layout.rs`, `wrap.rs`, `find_bar.rs`), `panels/` (transport strip, create-region and hotkeys dialogs, shared `ui.rs` / `modal.rs` widgets). |
| `crates/exaudio-shell/src/screens` | Everything outside the editor: Start, Settings, Extensions, accounts, updates. `screens/ui.rs` has the shared styling helpers. |
| `crates/exaudio-waveform`, `crates/exaudio-audio` | Peaks and line waveforms; decoding, playback engine and transport clock. |

Conventions the code relies on:

- **Behaviour goes in `exaudio-editor`, drawing in the shell.** A view calls `EditorModel::run(cx, |doc| doc.some_operation(..))`; the model applies the returned `Outcome` (status line, audio, scrolling, focus) and notifies the views. Views do not mutate the project themselves. Behaviour is tested headlessly in `crates/exaudio-editor/tests`.
- **A new action** is an `EditorAction` variant plus its `ACTION_DEFS` entry (section, EN/RU description, context, default keys) in `edit/keymap.rs`, dispatched in `EditorDoc::perform` (`edit/doc/actions.rs`) or, for app-level actions, `EditorScreen::perform`. The hotkeys dialog and the command palette list it without further wiring; the rules are in [`architecture/actions.md`](architecture/actions.md). Pointer gestures (modifier + click, drag or wheel) are not actions: their handling is in the timeline and transcript views, and `GESTURES` in `edit/keymap.rs` is the list the hotkeys dialog shows under "Mouse". A new or changed gesture needs its `GESTURES` row.
- **Every user-visible string has an English and a Russian form.** In views: `screens::ui::localized(cx, en, ru)`. Where no `cx` exists (text measurement, `exaudio-editor`): `exaudio_editor::i18n::localized(en, ru)`, and `localized_format!(en, ru, args…)` for templates. The status lines and refusals `EditorDoc` returns (`Outcome::status`, `EditError`) are built this way; the tests run in English and match the English text. Error context from `anyhow` under a refusal ("… failed: segment `x` was not found") is English only.
- **Sizes follow the interface zoom**: use rems, or multiply pixel constants by `zoom::ui_scale(window)`. Colours come from `cx.theme()`.
- **A transcript row has two render paths.** `transcript/row.rs` builds elements (editing, menus, chips, styled text, static rows); `transcript/fast_row.rs` paints plain rows directly. Both lay out through `transcript/row_style.rs`; a new cell or state has to reach both.
- **Some transcript surfaces only appear when an extension contributes them** through the row decorations of `exaudio_editor::transcript_model` (`contribution.rs`): the extra column, row patches (annotation kind, speaker note, styled text under the row text, word marks, chips, the timeline flag) and static rows. Today only Babel fills them (reviewer column, diff view, low-confidence review, annotation rows), and only Babel documents show the panels extensions dock at `PanelLocation::{Sidebar, Inspector, Overlay, Transport}`. Local documents never fill them, so a change to their rendering needs a look in the full build.
- **Extensions compile against the shell** (`EditorModel`, `editor::panels::{ui, modal}`, `screens::ui`). Changing those signatures can break Babel or Gold code; the workspace checks below catch it.

## Checks for contributors

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo nextest run --workspace --all-targets --locked
```

These cover every crate, Babel and Gold included, and pass without the Babel data bundle (the parity tests skip). CI additionally lints the editor-only build:

```powershell
cargo clippy -p exaudio-app --no-default-features --features palette,local,formats,basic-checks --locked -- -D warnings
```

`git config core.hooksPath .githooks` enables a pre-push hook that runs the format and Clippy checks. Native GUI behavior, audio playback, model setup and packaging are not covered by these commands and need a real run. Never use private service credentials or paid provider requests as a default test prerequisite.

## Extension development

Start with the [Rust SDK build/package guide](../sdk/rust/README.md) and [`hello-panel`](../extensions/examples/hello-panel). It describes the actual toolchain, component conversion, manifest, package layout, explicit grants and real-component smoke. Keep the [WIT contract](../wit/exaudio-extension.wit) and SDK compatible with the host version you target.

The [marketplace index repository](https://github.com/Nominy/exaudio-extensions) references packages released from each author's GitHub repository. The endpoint is `https://raw.githubusercontent.com/Nominy/exaudio-extensions/main/index.json`. Publish immutable versioned artifacts with their source identity, byte size, SHA-256 and requested permissions; an index record is not a license or security endorsement. Do not embed API keys or assume that manifest declarations automatically grant host access.

Native Rust extensions have application privileges. Installable WASM components use explicit typed host capabilities and resource limits, not arbitrary ambient filesystem/process/network access. Modes declare required extensions; removing a dependency while its mode is open is not a supported way to reduce the workspace's capabilities.

### Actions

Everything a user can invoke — menu items, toolbar buttons, keyboard shortcuts, hotkeys-dialog rows and command palette entries — is an action declared under `contributes.actions` in the extension manifest and registered in one `ActionRegistry`. The shape of a declaration, the `when` clause language, key chords, menu ids and the dispatch/activation rules are specified in [`docs/architecture/actions.md`](architecture/actions.md); the bundled `extensions/palette` extension is the smallest complete example (one action, one key, one menu placement, handler bound in `register`).

## Website development

`site/` is plain HTML, CSS and JavaScript with no build framework, package manager, external fonts or analytics. Russian is the no-JavaScript/default language. The explicit RU/EN controls persist `exaudio.site.language` in local storage when storage is available; system/browser language does not override the Russian default. Colors and existing brand headers follow `prefers-color-scheme`. `site/assets/` contains copies of the three source SVGs in `assets/brand/`; the Pages workflow refreshes those copies while assembling the artifact.

Open `site/index.html` for a quick static preview. For browser automation that requires HTTP, serve it with `python -m http.server 4173 --directory site --bind 127.0.0.1` and stop the server when finished.

`.github/workflows/pages.yml` runs only for `Nominy/exaudio` on `main`, uses a hosted Linux runner and Pages OIDC permissions, and substitutes the **actual** `actions/configure-pages` `base_url` into canonical/OG URLs, `sitemap.xml` and `robots.txt`. Raw source contains the deliberate `__BASE_URL__` build token; the published artifact must not. The assembly step fails on missing or unresolved tokens. Pages must use **GitHub Actions** as its source. A local file preview is not proof of canonical URL correctness or deployment.

Visual acceptance should cover RU/EN, retained language after reload, light/dark themes, 320/375/768/1440 px widths, keyboard-only navigation, visible focus, 200% zoom, reduced motion, blocked local storage and the no-JavaScript Russian page. Check that all download/issue/SDK links resolve once their repositories and releases exist. A visually successful preview does not establish that a release exists.

Screenshots in `site/assets/*.webp` (`editor-interview-draft`, `start-screen`, `speaker-menu`, `ai-draft-dialog`) are real captures of the app with the synthetic "Interview" demo, cropped below the window title bar and converted with `magick <shot>.png -crop WxH+0+31 +repage -quality 82 <name>.webp` at ≤1600 px wide. `img` elements carry actual dimensions, a Russian `alt` and an English `data-en-alt`. Never show private tasks, credentials or someone else's recording; the README hero image is the same `editor-interview-draft.webp`.
